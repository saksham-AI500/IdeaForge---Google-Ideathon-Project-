## What this project is

IdeaForge is a private AI workspace that helps a user develop a rough idea through Gemini-guided conversation, and automatically preserves *why* the idea changed over time — not just what it became.

**Positioning line (use in UI copy, README, comments where relevant):**
> "Most AI tools help you generate an idea. This one helps you watch an idea get better — and remembers why."

**Problem it solves:** AI chat tools treat every conversation as disposable. The reasoning behind a pivot — the assumption that got challenged, the insight that caused a change — disappears when the chat closes. IdeaForge preserves that reasoning as structured, navigable history.

**The one differentiator this submission is built around:** the **Idea Evolution Engine** — every meaningful revision to an idea creates a new version with an explicit "what changed" and "why changed," generated by Gemini from the actual conversation. Everything else in the app supports this one feature.

## Core workflow (MVP scope — build only this)

```
CAPTURE → CLARIFY → CHALLENGE → REVISE → NEW VERSION CREATED (Evolution Engine)
                                              ↓
                                      ASK MY IDEA (grounded Q&A over version history)
```

- **Capture:** user enters a rough idea (free text)
- **Clarify:** Gemini asks 2–3 targeted questions about problem/users/goal
- **Challenge:** Gemini identifies one weak assumption and pushes back — not just validates
- **Revise:** user updates the idea based on the challenge
- **Evolve:** system detects meaningful change → creates new version → Gemini writes a short `whyChanged` summary from the conversation
- **Ask My Idea:** user asks "why did I change X?" → Gemini answers using stored version history as prompt context, no retrieval infra needed

## Gemini resilience — model fallback ladder

Per Codelab Custom Instructions, Gemini calls must fall back across models on recoverable failure, not just show a generic error. Implementation:
1. Primary call to the main configured Gemini model.
2. On a recoverable error (timeout, rate limit, transient 5xx), retry once against a secondary/fallback Gemini model.
3. Only after the fallback also fails does the app show the user an error state.
4. Non-recoverable errors (e.g. invalid input, auth failure) should not trigger the fallback ladder — fail fast with a clear message instead.

This applies to every Gemini call in the app: Clarify, Challenge, Evolution summary, Ask My Idea.

## Persistence-failure recovery (Retry Save)

Per Codelab requirement: user input must never be silently lost on a Firestore write failure.
- On any failed save (idea revision, version creation, message persistence), keep the user's unsaved input visible in the UI — do not clear the input field or navigate away.
- Show a specific, clear error message (not generic "something went wrong").
- Provide an explicit **Retry Save** action that re-attempts the same write with the same data, without requiring the user to re-type anything.

**Explicitly excluded — do not suggest or scaffold these:** vector databases, graph databases, LangChain/LlamaIndex, Cognee-style frameworks, BigQuery, Pub/Sub, any embedding pipeline. See AGENT_RULES.md for why.

## Data model (final)

```
users/{uid}/
  ideas/{ideaId}
    title, currentContent, createdAt, updatedAt
    versions/{versionId}
      content, whatChanged, whyChanged, previousVersionId, createdAt
    conversations/{conversationId}
      messages: [{role, text, timestamp}]
```

Every read/write must be scoped to `request.auth.uid == uid` in the path. This is judged under the "Security" pillar — get it right, don't approximate it.

## Judging pillars (design every feature against these)

- **Authenticity** — original concept, genuine custom approach → the Evolution Engine + honest confirmed-vs-roadmap framing in the README
- **Usability** — intuitive, accessible, seamless UX → small scope built cleanly, not large scope built roughly
- **Stability** — reliable, bug-free, no crashes on stage → this is why scope is deliberately small
- **Security** — data protection, auth, secure infra → Secret Manager, Firestore isolation rules, server-side-only Gemini calls

## Gemini prompt templates

**Clarify:**
```
The user has shared a rough idea: {idea}. Ask 2–3 sharp clarifying questions
about the core problem, target users, and goal. Do not suggest solutions yet —
only clarify.
```

**Challenge:**
```
Given this idea and the user's answers: {context}. Identify ONE assumption
this idea depends on that may be weak or unproven. Explain why it's risky.
Do not be encouraging for its own sake — be direct.
```

**Evolution summary (on version creation):**
```
Compare the previous version: {previousContent} with the new version:
{newContent}, given this conversation context: {conversationExcerpt}.
In 1–2 sentences, state what changed and why, from the user's own reasoning —
do not invent motivations not present in the conversation.
```

**Ask My Idea (grounded Q&A):**
```
Here is the full version history of this idea: {versionHistoryWithWhyChanged}.
Answer the user's question using only this history.
Question: {userQuestion}
```
